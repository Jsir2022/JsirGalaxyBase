# BetterQuesting 内容兼容、迁移与正式切换路线

日期：2026-09-17
状态：M.1 自动验收完成；下一实施点为 M.2 Task/Reward 行为兼容

## 产品决策

在继续设计职业、贡献或其他新玩法前，先让现有 GTNH BetterQuesting 内容能够被 Base 安全吸收并实际使用。
当前优先目标不是创造新任务体系，而是建立以下完整链路：

`BQ 内容清点 → 定义导入 → 行为兼容 → 玩家进度合并 → 影子双算 → 可回滚切换`

“能够读取 JSON”不等于兼容完成。只有导入后的任务能够在 Minecraft 中按原语义推进、完成、重复并交付奖励，
才可标为行为兼容。未知或不完整类型必须失败闭合，禁止静默删除 Task、Reward 或参数。

## 当前基线

已经具备：

- `galaxy-quest-bq-importer` 只读解析器；
- BQ 任务、章节、章节顺序和玩家进度的内存模型；
- Standard Task/Reward 参数转换与兼容性报告；
- 多服务器玩家进度冲突分析；
- 离线 BQ/Base 进度差异分析基础；
- Base Quest Core、PostgreSQL 运行时、Minecraft 检测器和 UI2 任务中心；
- PLAYER/PARTY/TEAM/PUBLIC 跨服主体和逐成员奖励归属。

当前 importer 只读取并报告，不写 PostgreSQL，不生成可执行迁移批次，也不进入运行 JAR。Quest 生产开关默认
关闭，BetterQuesting 仍是现网任务系统。

## 支持的 BQ 输入形态

首要输入是 GTNH 使用的拆分导出目录：

```text
DefaultQuests/
├── Quests/**/*.json
├── QuestLines/<章节目录>/QuestLine.json
├── QuestLines/<章节目录>/*.json
└── QuestLinesOrder.txt
```

玩家进度来自各服务器独立的 UUID JSON 文件。单文件旧式任务数据库不是当前已验证输入；如现网存在该格式，
应新增独立适配器，归一化为相同的迁移清单，而不是让 PostgreSQL 写入器理解多种 BQ 文件结构。

## 阶段路线

### M.0：真实内容清点与固定样本

- 对只读副本执行任务、章节、Task/Reward 类型、参数形状及资源引用清点。
- 为输入目录、每个源文件和整体内容生成稳定 SHA-256。
- 固定脱敏测试样本和预期统计，避免后续只使用人工构造的小样本证明兼容。
- 区分标准 BQ 类型、GTNH 扩展类型、未知类型和仅能解析但尚不能运行的类型。
- 不连接生产 PostgreSQL，不修改 BQ 目录。

### M.1：任务定义与章节迁移闭环

- 将解析结果转换为不可变迁移清单，包含批次 ID、来源摘要、任务/章节内容哈希、依赖关系和兼容结论。
- 校验 UUID 重复、缺失前置、前置环、章节悬空、重复放置、章节顺序、资源边界及参数完整性。
- 对每个 Task/Reward 输出 `SUPPORTED / ADAPTED / BLOCKED / UNKNOWN`；存在阻塞项时整批禁止提交。
- 增加 PostgreSQL staging/dry-run、原子提交、幂等重跑、审计记录和整批回滚合同。
- 相同来源和内容不得产生新版本；已有 UUID 但内容变化必须产生显式差异和受控新版本，不得覆盖已发布版本。
- UI2 管理终端显示新增、相同、变化、阻塞和未知项，并提供有界差异详情。
- 导入隔离 PostgreSQL 后，玩家任务中心必须能完整浏览章节、任务、前置、图标、目标和奖励。
- 本阶段不导入玩家进度、不启用事实检测、不发放奖励。

### M.2：Task/Reward 行为兼容

按真实任务库使用频率推进，而不是按类名数量推进：

1. retrieval、optional retrieval、NBT、OreDict 与库存分配；
2. crafting、smelting、anvil 与 statistics 模式；
3. hunt、block break；
4. location、meeting、item/entity interact；
5. fluid 与模组容器；
6. XP、scoreboard、checkbox；
7. item、XP、scoreboard、command、quest completion、choice 奖励；
8. GTNH 或其他模组注册的扩展类型。

每个类型都必须覆盖配置解码、事实采集、进度归约、完成、重复周期、自动领取和奖励结果。能够解析但没有
Minecraft 事实入口或交付处理器的类型不得标为 `SUPPORTED`。

### M.3：跨服务器玩家进度迁移

- 同时读取 S1、S2、Lobby 等来源的只读副本，以玩家 UUID 和任务 UUID 对账。
- 完成、领取、Choice、时间戳、向量进度和重复周期分别定义合并规则，禁止整文件覆盖。
- 已领取状态优先防止重复发奖；无法证明安全的冲突进入人工审计队列。
- 旧 BQ Party 进度必须显式映射为 PLAYER/PARTY/TEAM/PUBLIC，不把队伍 UUID 当玩家 UUID。
- 生成玩家级 dry-run、冲突原因、批次审计、幂等重跑与整批回滚证据。

### M.4：管理员诊断与受控修复

- 在 UI2 管理终端提供定义、进度、奖励、成员关系、交付队列和迁移批次诊断。
- 修复操作只接受稳定业务键、版本绑定和有限白名单动作。
- 重算、重试、重置、修复必须支持 dry-run、权限检查、审计、幂等和明确影响范围。
- 客户端不得上传完成状态、奖励结果、玩家所有者或“安全”结论。

### M.5：BQ/Base 实时影子双算

- BetterQuesting 继续成为唯一发奖方；Base 同时接收事实并计算，但禁止发奖。
- 按玩家、任务、Task 类型、周期和时间窗口输出一致、BQ 领先、Base 领先、分歧及不可比较原因。
- 对统计量、NBT、OreDict、流体、队伍和重复任务单独统计差异。
- 只有约定观察期内差异收敛，或每项差异均有明确迁移例外，才允许进入正式切换。

### M.6：灰度与正式切换

1. 备份并校验全部 BQ 定义和玩家进度；
2. 冻结 BQ 编辑；
3. 执行最后一次幂等增量迁移；
4. 禁止 BQ 领取，启用 Base PostgreSQL Quest Runtime；
5. 在灰度链验证任务推进、Choice、领取、离线交付和恢复；
6. 保留可执行回滚窗口；
7. 证据通过后终端成为唯一入口；
8. 最后才移除 BetterQuesting 运行依赖，并保留只读备份与迁移审计。

## 工作量与风险

| 工作包 | 相对工作量 | 主要风险 |
|---|---:|---|
| M.0 内容清点 | 小到中 | 样本不完整导致虚假兼容 |
| M.1 定义/章节迁移 | 中到大 | 幂等版本、依赖、回滚与差异展示 |
| M.2 行为兼容 | 最大 | GTNH 扩展、NBT、OreDict、流体和周期差异 |
| M.3 玩家进度合并 | 大 | 重复发奖、Choice、重复周期、旧队伍语义 |
| M.4 诊断修复 | 中到大 | 高权限操作的审计与失败恢复 |
| M.5 影子双算 | 大 | 双系统事实口径、性能和差异解释 |
| M.6 正式切换 | 中 | 生产安全、灰度证据和回滚窗口 |

最耗时的不是 JSON 语法解析，而是证明每一种导入内容在运行时保持原 BQ 行为。

## M.1 自动验收

当前状态：**自动验收完成**。实现包含稳定批次/来源哈希、逐元素兼容矩阵、正式编辑类型注册表参数校验、
依赖与章节结构校验，以及明确区分的两个入口：`dry-run` 永不写库；`preview` 是必须显式确认的审计写入。
隔离 PostgreSQL 已覆盖 PREVIEW/BLOCKED、原子提交、相同批次重跑、内容变化受控升版、整批回滚、后续版本保护
和故障事务回滚。UI2 管理终端可查看最近批次的状态、计数和有界诊断，玩家任务中心能够浏览导入的章节、前置、
目标与奖励。M.1 完成不代表运行行为、玩家进度或生产切换已经完成。

- 相同输入两次生成字节稳定的迁移清单和相同批次语义。
- 缺失/重复 UUID、前置环、悬空章节、未知类型和非法参数均失败闭合。
- dry-run 不产生数据库写入；提交要么整批成功，要么整批回滚。
- 相同批次重复提交不增加定义版本、章节版本或审计行。
- 回滚只能撤销该批次引入且尚未被后续版本依赖的内容；存在后续依赖时拒绝并给出影响项。
- 隔离 PostgreSQL 真库覆盖提交、重跑、冲突、故障回滚及回滚重试。
- UI2 覆盖三档窗口、长名称、大章节、阻塞项、差异详情和分页。
- 最终运行 JAR 不包含 importer、Gson CLI、BQ 类、BQ GUI/Packet 或 JSON 存储。
- 执行 Quest 三模块、UI2、根测试、视觉报告、`assemble`、`verifyUi2SelfContained` 和
  `git diff --check`。

最终证据（2026-09-17）：788 项测试、71 项环境条件跳过、0 failure/0 error；258 张视觉快照均为
`SUMMARY|issues=0`。运行 JAR 自包含检查通过，且只包含 importer 来源声明，不包含 importer/Gson CLI/BQ
运行类。审计增量迁移仅在隔离 PostgreSQL 16 中重复执行验证，未连接生产数据库。

## M.1 默认边界

- 只使用用户明确提供的只读 BQ 内容副本，不扫描或修改生产目录。
- 不执行生产 DDL，不连接生产 Quest schema。
- 不导入玩家进度，不启用 Base Quest，不发奖励，不部署，不停用 BetterQuesting。
- 不把未知类型降级成 checkbox、文本说明或自动完成任务。
- 不把 importer 打入 Base 运行 JAR。
- 职业、贡献和新公共玩法继续暂停，直到 BQ 兼容与迁移主链达到可用门槛。

## 下一长期目标

M.2 应使用用户明确提供的只读 `DefaultQuests` 副本生成真实类型/参数频率清单，并按频率逐类证明 Task/Reward
的配置解码、事实采集、进度归约、重复周期和交付语义。任何尚无 Minecraft 事实入口或奖励处理器的类型必须
继续标记为 BLOCKED，不得因 M.1 可以导入定义而宣称行为兼容。

M.1 完成不代表 BQ 已替代。之后仍必须完成 M.2 行为兼容、M.3 玩家进度迁移、M.5 影子双算和 M.6 切换门禁。
