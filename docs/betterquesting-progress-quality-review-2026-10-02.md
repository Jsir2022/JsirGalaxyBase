# BQ 替代进度与代码质量收口（2026-10-02）

## 结论

当前在 M.2「行为兼容」，不是“只差跨服”，也不是 BQ 已替代。已有真实的背包检测、消费提交、进度归约、奖励资格和交付实现，以及任务中心、编辑和导入工具；问题在于运行可靠性、兼容证据和生产门禁仍不足。

本轮只做源码审查与文档整理，没有修改业务代码、提交或部署，没有访问生产数据库或玩家进度。下列发现是源码路径确认，不是已经复现的现网事故。

## 优先修复项

| 优先级 | 发现与依据 | 影响与整改建议 |
|---|---|---|
| P1 | `QuestGameplayEventHandler.java:166` 每 60 tick 直接调用 `sink.reconcileLockedProgress`，没有 `submit` 的异常边界；调用链进入 JDBC 事务 | 数据库异常可逃出 tick 回调。为复评建立明确失败边界、退避和诊断，并用故障注入证明不会影响服务器 tick |
| P1 | `QuestGameplayEventHandler.java:142` 背包每 20 tick 同步提交；`QuestEvaluationPlanner.java:35` 每次调用 `findAllPublished`；`JdbcQuestDefinitionRepository.java:119` 查询并解码全部已发布定义 | 服务器主线程承担数据库等待与全任务扫描。未测 TPS，不能量化损失，但结构风险明确。缓存发布定义、按事实类型索引、批量读取进度、抑制未变化的背包快照；队伍租约心跳与内容变化分开处理 |
| P1 | `QuestGameplayEventHandler.java:223` 的 `submit` 捕获异常后仅记录日志，没有保留事实重试 | 数据库短暂失败会丢失一次性合成、击杀、破坏事件；背包周期观察不能补回这些事件。保留不可变事实及原幂等键，建立有界有序重试；若要求进程崩溃后恢复，需持久化机制 |
| P1 | `QuestPostgresIntegrationTest.java:90` 测试 URL 未设置时回退 `galaxy-base`；`BqMigrationDatabaseIntegrationTest` 等也继承数据库环境变量 | 开发容器继承连接变量时，测试可能在非隔离数据库创建测试 schema。必须显式指定测试数据库并校验隔离身份；随机 schema 不是充分隔离 |
| P1/P2 | `MinecraftItemRewardDeliveryHandler.java:256` 先掉落实体，完成标记在后续 `272–278` 才保存 | 实体掉落与持久化回执之间有崩溃重放窗口，不能宣称端到端 exactly-once。需明确满背包延期或可幂等交付的策略，并补崩溃边界测试；不要未经决定改变玩法 |

性能整改不能直接把在线玩家、背包或 ItemStack 放到后台线程访问。应在游戏线程获取不可变快照，后台只处理纯数据，并明确结果应用边界。

## 已有代码的价值与质量

- Core、PostgreSQL、BQ importer 和 Minecraft 适配分层明确，纯 Java 逻辑可独立验证。
- 认证玩家身份、定义版本、周期、事实幂等键、冻结奖励接收者和队伍库存租约已经形成实现，并非只有设计文档。
- 重复提交、消费恢复、奖励恢复、NBT 匹配与主体归属有针对性测试；这些不等于真实 Forge、世界实体与数据库故障下全部正确。
- 当前集成层仍有同步数据库热点和失败边界缺口。代码具备可继续完善的基础，但不能据此批准生产替代。
- 文档原先把基础能力“已实现”与 BQ 行为“兼容通过”混用；本次统一以能力矩阵为权威阶段入口，历史 Worklog 保留但不再充当当前待办。

最近的真实定义聚合中，retrieval 3,863 次、optional_retrieval 1,267 次，全部 Task 合计 5,620 次，背包检索约占 **91.3%**。这是任务出现次数，不是独立 Quest 数，也不证明玩家是否使用观察站。

用户本轮确认背包物品检测为主线。观察站邻接库存是已知辅助能力差异，**延后处理，不再作为当前必须先设计的交互入口**；不掩盖差异，也不让它阻挡背包主链的整改。

## 本轮验证记录与限制

- CodeGraph `status/sync` 显示索引已更新；`impact QuestGameplayEventHandler.onPlayerTick --depth 2` 返回 34 个影响符号。
- 对事件入口、求值规划和奖励交付文件执行 `affected` 未识别关联测试。这是图谱覆盖限制，不表示没有测试；测试选择仍需人工核对。
- 首次测试命令把未限定的 `test` 和 Quest 过滤器传播到 UI2 子项目，产生“No tests found”。这是命令选择错误，不计为代码测试失败或全套通过。
- 随后改为独立子模块测试与限定根 `:test`，构建插件 `gtnhconvention` 初始化发生 `SocketTimeoutException`，重试仍在测试前失败。**本轮未取得有效全量自动验收，不报新的通过数量。**
- 测试尝试显式清除数据库连接环境变量，避免上述默认连接风险；未运行会读取生产配置回退的无差别根项目测试。
- 原有 748 项/66 跳过等数字属于历史检查点，不作为当前大工作树的最新质量证明。文档整理后单独检查 `git diff --check`。

## 下一轮固定顺序

1. 加固测试数据库隔离与构建可复现性，让自动验证可信。
2. 修复 tick 异常边界、一次性事实重试，以及背包轮询全量数据库扫描。
3. 明确并修复奖励满背包崩溃边界，完成“背包检测 → 提交/消费 → 完成 → 领奖”合成与故障测试。
4. 再推进 BQ 参数与队伍兼容矩阵；仍未证明的类型保持 BLOCKED。
5. 通过有效构建后形成可追溯代码检查点，再考虑玩家迁移、影子和切换；不新增职业玩法或观察站。
