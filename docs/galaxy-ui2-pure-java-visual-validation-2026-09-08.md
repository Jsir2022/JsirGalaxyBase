# Galaxy UI2 纯 Java 视觉正确性闭环

## 1. 目标与验收边界

本方案只自动验证 UI 的结构和基本显示正确性，不替代玩家对交互手感、信息组织和视觉偏好的人工验收。
日常开发不得再依赖用户逐页进入 GTNH 并人工截图，正式页面应能用固定业务快照在纯 Java 环境生成可复查证据。

自动验收范围：

- 组件、文本、原生槽位占位区和外部绘制区不越出终端窗口；
- 非叠放语义的内容不重叠，裁剪栈与变换栈平衡；
- 标题、正文、按钮和表格文本遵守字号上限、换行、省略或滚动合同；
- Dialog、Tooltip、Toast 和菜单保持在窗口内且层级正确；
- 图表有数据时产生可见几何，稀疏、单点和空数据具有明确降级画面；
- 正常、加载、空、失败、长文本和极大数值状态均可渲染；
- `350x193`、`427x240`、`620x340` 三档逻辑视口都有证据。

人工验收继续负责拖放、Shift-click、键盘操作、动画观感、信息是否顺手以及主题的主观质量。

## 2. 单一页面实现

生产页面与预览必须共用同一个 UI2 Document，不为 Java2D 重写业务页面：

```text
固定测试 Snapshot ─┐
真实网络 Snapshot ─┴→ State / Reducer → UI2 Document → UiRuntime / DrawList
                                                        ├→ Minecraft Renderer
                                                        └→ Java2D Renderer
```

`ItemStack`、Slot、地图和其他 Minecraft 专属对象继续停留在平台桥之后。纯 Java 预览用稳定外部区域 ID、
注册名、数量和确定性占位资源表达，只验证位置、尺寸、遮挡与周边布局，不声称验证 Minecraft 的真实绘制结果。

## 3. 产物与失败规则

无头任务当前统一为：

```text
scripts/render-ui2-visuals.sh
```

输出目录 `ui2-demo/build/ui-lab/` 包含：

- 每个场景和尺寸的 PNG；
- `.drawlist.txt` 绘制命令；
- `.ui2.txt` 组件树、最终边界和结构审计；
- `index.html` 截图画廊。

逐步升级为正式页面视觉任务后，以下情况必须使任务失败：越界、非法重叠、未声明的文本溢出、栈不平衡、
重复外部区域 ID、有数据而无图表几何、Modal 越界、可见交互控件无标签或命中区，以及正常页面接近整块单色。
PNG 不做跨 JDK 的严格逐像素比较，以结构断言、关键区域采样和容差图像差异为准。
Java2D 通过 `UI2_PREVIEW_FONT` 使用主机提供的测试字体；脚本只读挂载字体，不复制到源码或运行 JAR，
也不改变正式终端继续使用 Minecraft 当前字体与资源包的决定。

## 4. Mod 内调试截图

UI2 Screen 与 Container 宿主实现只读 `Ui2DebugCaptureSource`。在现代终端页面按 `F9` 时保存：

- `screenshots/ui2-debug-<Screen>-<time>.png`：Minecraft 当前 Framebuffer；
- 同名 `.ui2.txt`：逻辑视口、组件树、结构告警和 DrawList。

它不自动操作页面，不上传文件，也不改变业务状态；非 UI2 页面按 F9 只显示不适用提示。该入口用于人工发现实机问题后，
让开发者同时取得画面和结构证据，而不再只能依据截图猜测。

## 5. 分阶段实施

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| V.0 | 通用结构快照、三档 UI Lab、HTML 画廊、Mod F9 截图与侧车文件 | 自动验收完成 |
| V.1 | 提取纯 Java 终端壳、页面预览合同、保守文字度量与固定测试 Snapshot | 自动验收完成 |
| V.2 | 首页、设置、资产中心接入正式 Document 预览；补齐文本/槽位审计 | 自动验收完成 |
| V.3 | 标准市场目录、详情、图表、下单浮层和订单中心接入；图表可见性断言 | 实施中：目录/详情/折线/成交量/稀疏门禁完成，正式交互适配与订单中心待迁移 |
| V.4 | 银行、通知、传送、地产及其他页面覆盖；生成统一视觉报告 | 未开始 |
| V.5 | 将视觉任务纳入常规验证，人工仅承担交互和主观视觉验收 | 未开始 |

任务平台 Q.6 已复用同一视觉闭环加入玩家任务中心的浏览、详情、空态和错误态；三套主题、三档视口合计
新增 36 个快照，当前统一报告为 99 个终端快照。章节与任务列表不再由 Document 固定截断，页索引、总数、
查询词和翻页动作均属于纯模型合同，正式网络接入后继续使用同一个 Document。

正式 Document 原位于根 Mod 源集，不能让独立 Demo 反向依赖根项目。现已新增只依赖 `ui2-core` 的
`ui2-terminal`，并完成终端壳、首页、设置、资产中心及只读摘要页的纯 Java Document；根 Mod 通过适配器
提供真实快照、动作与 `ItemStack`。V.1 后续页面继续遵循同一依赖方向，
根 Mod 只保留 Minecraft Snapshot 转换、ItemStack/Slot/地图桥和网络 Effect，禁止通过复制页面绕开依赖方向。

当前依赖盘点还确认：旧标准市场交互适配和订单中心仍直接使用 `ItemStack`，地产依赖
地形缓存与旧地图面板，资产状态和动作也携带 `ItemStack`。V.1 应先定义平台无关 `VisualItem`、`ExternalVisualRegion`
和纯图表命令；不能把 Minecraft 类伪造进预览模块。纯图表现已能由 Java2D 与 Minecraft 消费相同的
`CHART_LINE/CHART_VOLUME` 命令，V.3 剩余工作是接回下单、撤单、订单中心状态与正式市场适配。

## 6. 默认约束

- 不建设最小 Minecraft 客户端，不自动登录或连接服务器；
- 不用鼠标键盘脚本模拟玩家交互；
- 不修改服务端业务、数据库、资产、市场或地产真源；
- 截图功能不进行网络上传；
- Java2D 预览不是生产渲染器，真实 GL、字体资源包和原生物品观感仍保留人工抽检。
