# 市场操作回执、快速撤单与订单资产中心设计 v2

日期：2026-08-12

最近修订：2026-08-15

## 1. 文档目的

这份文档定义银河终端标准商品市场的三项正式产品需求：

- 交易动作必须通过终端右上角泡泡提供清晰、可靠、可追溯的即时回执。
- 商品详情页保留 `买入 / 卖出 / 撤单` 三个即时动作；`撤单` 打开当前商品的活动委托弹窗，不执行无目标撤销。
- 市场与仓库共同提供跨商品的 `订单与资产中心`，承载当前委托、成交记录、交付资产、异常恢复和历史查询。

本文是产品与交互合同，不表示当前代码已经完成。后续实现、测试和验收均以本文为准。

## 2. 已锁定的交互决策

### 2.1 商品详情页主按钮

商品详情页继续只保留三个主按钮：

1. `买入`：打开买入订单弹窗。
2. `卖出`：打开卖出订单弹窗。
3. `撤单`：打开当前商品的活动委托弹窗。

`撤单` 不是“撤销最近一单”或“撤销全部”的快捷命令。弹窗只查询当前玩家、当前商品且仍有剩余量的 `OPEN / PARTIALLY_FILLED` 委托，并要求玩家点选具体订单。没有可撤委托时按钮可保持可点击并展示明确空态，也可在快照已确定为空时禁用并提供悬浮原因。

活动委托弹窗每行至少显示：买卖方向、市场/限价类型、委托价、原始数量、已成交量、剩余量、创建时间和精确撤单按钮。点击后仍需二次确认，服务端重新校验订单归属、版本、状态和剩余量。

### 2.2 订单与资产中心的产品边界

`订单与资产中心` 是独立的终端内容页，不是狭窄浮窗。它负责跨商品管理当前玩家的委托、成交、交付资产和失败操作；可从市场顶栏/总入口进入，也可从仓库页进入。两个入口打开同一服务端数据视图，不建立第二套资产真相。

默认进入 `当前委托`，显示所有商品仍可能变化的订单。玩家可使用筛选条件收窄结果：

- 商品范围：`全部商品 / 当前商品`
- 方向：`全部 / 买入 / 卖出`
- 状态：`全部 / 可撤 / 部分成交 / 已成交 / 已撤销 / 失败 / 待恢复`
- 时间：`最近 24 小时 / 7 天 / 30 天 / 全部`

当玩家从某一商品上下文进入中心时：

- 中心默认仍显示当前玩家的全部商品记录，承担统一管理入口职责。
- 页面保留来源商品上下文，工具栏提供一键 `本商品` 筛选；随后可继续叠加 `买单 / 卖单`、状态和时间筛选。
- `全部商品` 只表示当前登录玩家自己的全部商品记录，不包括其他玩家委托或全市场流水。
- 返回详情页时保留此前选择的商品和图表周期。

历史成交只是中心中的辅助查询视图，用于复盘和审计，不再占据商品详情的主按钮。高频动作在详情页完成，跨商品管理在中心完成，单次精确撤销在活动委托弹窗完成。

## 3. 订单与资产中心信息架构

### 3.1 账户摘要带

页面顶部先显示一条紧凑账户摘要，避免玩家在订单、银行与仓库间反复跳转：

- 银行可用余额与冻结资金
- Base Vault 已用/总格位
- 当前活动委托数量
- 待交付或待收货数量
- 需要人工关注的恢复操作数量

摘要数据只读，来自银行、Base Vault、市场订单和恢复账本。资产移动仍在仓库页完成，中心不得自行复制一套存取逻辑。

### 3.2 顶部管理工具栏

历史页顶部固定展示筛选工具栏，不随记录列表滚动：

- 搜索：按正式商品名称或物品键查询，由服务端执行，不局限于当前页
- 商品：`全部商品 / 本商品`
- 方向：`全部 / 买入 / 卖出`
- 状态：`全部 / 进行中 / 已成交 / 已结束`
- 时间：`全部 / 24 小时 / 7 天 / 30 天`
- 排序：默认按最近更新时间倒序
- 清空：同时清除搜索词和全部筛选，回到第一页

任一筛选改变后回到第一页，并由服务端重新查询。列表只显示当前页，底部展示总记录数、当前页和上一页/下一页；不得先下载完整历史再由客户端过滤。

第一版使用紧凑的两行工具栏和结构化订单表，不使用四个占满横向空间的大按钮。筛选控件必须始终带字段前缀，例如 `状态: 进行中`，玩家可以直接判断当前约束；`清空` 是显式取消所有筛选的统一入口。

### 3.3 标签页

中心固定使用四个标签：

- `当前委托`：显示仍可能变化的订单，是精确撤单的唯一入口。
- `成交记录`：显示真实成交明细和订单累计成交结果。
- `资产与交付`：显示 Base Vault 收发、待交付、满仓、冻结/解冻和恢复状态。
- `历史查询`：查询已经结束的委托与历史操作，默认不干扰当前委托工作流。

### 3.4 当前委托

每一行必须是结构化订单记录，至少显示：

- 商品真实图标与正式名称
- 买入或卖出
- 市价或限价
- 委托价格
- 原始数量
- 已成交数量
- 剩余数量
- 平均成交价
- 冻结资金或预留库存
- 创建时间
- 当前状态
- 订单编号的短显示

仅当服务端判定订单仍可撤时，该行显示 `撤单` 操作。不得再提供无法确定目标的全局撤单按钮。

首轮订单表固定显示方向、正式商品名、价格、成交量/总量、剩余量、中文状态和创建时间。原始 `product_key` 与英文枚举只作为内部数据，不直接作为玩家主要阅读内容；开放订单的撤单按钮固定在对应行末，不得挤压页脚或覆盖下一行。

### 3.5 精确撤单

点击某一行的撤单操作后，确认弹窗必须展示：

- 商品和订单编号
- 买卖方向
- 委托总量、已成交量和剩余量
- 预计返还的资金或账户仓库存
- 资产返还目标
- 当前不可执行原因（如有）

服务端必须在执行时重新校验订单所有权、版本和状态。若订单在确认期间已成交或已撤销，应返回最新状态并刷新该行，不得将其升级成资产恢复异常。

### 3.6 成交记录

成交记录至少显示：

- 商品
- 买卖方向
- 成交数量
- 成交价格
- 成交金额
- 手续费
- 净收入或实际支出
- 成交时间
- 对应订单
- 交付状态

部分成交应显示为真实的多笔成交或可展开的订单成交汇总，不能只展示最终订单状态。

### 3.7 资产与交付

该标签只承载需要玩家关注的异常或延迟状态：

- Base Vault 满仓导致的待交付
- 撤单返还延迟
- 银行冻结或解冻失败
- 操作被拒绝
- `RECOVERY_REQUIRED` 及管理员处理结果

正常完成的自动交付不长期占据该页面，只保留在操作记录中。

### 3.8 历史查询

历史查询用于回答“过去发生过什么”，不是当前交易页的主操作。它复用搜索、商品、方向、状态、时间和服务端分页合同，展示已经成交、撤销、拒绝或完成恢复的记录。默认时间范围可为最近 30 天，并允许切换到全部；任何筛选都必须能通过 `清空` 一键解除。

### 3.9 页面入口建议

- 市场总入口顶栏增加订单簿/清单图标，进入 `订单与资产中心` 的 `当前委托`。
- 仓库页顶栏增加资产概览图标，进入同一中心的 `资产与交付`。
- 商品详情第三按钮固定为 `撤单`，只打开当前商品活动委托弹窗，不跳转全局中心。
- 泡泡回执中的 `查看订单` 可直接定位中心中的具体订单；`查看交付` 可定位资产与交付记录。

## 4. 右上角泡泡回执

### 4.1 位置与层级

泡泡固定显示在银河终端内容区右上角、顶栏下方，不使用容易被其他界面遮挡的全局 Minecraft HUD 角落。

层级固定为：

`正文 < Hover < 泡泡回执 < Modal 确认弹窗`

当 Modal 仍然打开时，动作处于提交中状态；服务端结果返回后关闭或更新 Modal，再显示泡泡。

### 4.2 回执类型

- `SUCCESS`：绿色，表示服务端已经确认完成。
- `WARNING`：黄色，表示部分完成、状态已变化或需要后续处理。
- `ERROR`：红色，表示操作被拒绝或失败，且没有被错误地报告为成功。
- `INFO`：只用于重要状态变化；自动刷新不产生泡泡。

### 4.3 回执内容

每条回执至少包含：

- 图标和严重级别
- 简短标题，如 `卖单已提交`
- 玩家可理解的结果摘要
- 商品、数量或订单短编号
- 可选操作：`查看订单 / 查看详情`

失败回执不得直接暴露 JDBC、SQL、Java 异常或内部账户字段。例如：

```text
买单提交失败
付款账户配置异常，本次未冻结资金。
错误码：MARKET_BANK_ACCOUNT_INVALID
```

服务端保留完整异常和 `requestId` 供审计，客户端只接收稳定的原因码及安全文案。

### 4.4 生命周期

- 成功回执默认显示约 3 秒。
- 警告和失败回执默认显示 6 至 8 秒。
- 同一 `requestId` 只展示一次。
- 页面刷新、快照替换或进入其他终端页不得导致重复展示。
- 最多同时显示三条；更多回执进入队列。
- 玩家可主动关闭泡泡。

## 5. 持久操作记录

泡泡是即时反馈，不能代替历史。终端右上角应提供消息或回执入口，保存最近至少 20 条显式玩家操作：

- 操作时间
- 操作类型
- 成功、警告或失败
- 商品与数量
- 订单编号
- 安全错误码
- `查看订单` 或 `查看详情` 跳转

操作记录与市场历史职责不同：

- 操作记录回答“我刚才点的操作发生了什么”。
- 市场历史回答“我的订单、成交和资产交付现在是什么状态”。

## 6. 客户端与服务端合同

### 6.1 独立动作结果

交易命令结果与市场状态快照必须分离：

- `MarketActionResult`：一次性动作结果，驱动泡泡和操作记录。
- `MarketSnapshot`：可重复刷新，驱动盘口、余额、委托摘要和行情。

客户端不得从页面正文通知、异常字符串或快照差异猜测一次操作是否成功。

建议动作结果至少包含：

- `requestId`
- `operationType`
- `severity`
- `reasonCode`
- `title`
- `summary`
- 可选 `orderId / productKey / quantity`
- `createdAt`
- 可选页面跳转目标

### 6.2 个人历史查询

历史数据必须由服务端按登录玩家身份查询并分页返回。客户端可提交筛选条件，但不得提交可信的玩家账户 ID。

查询合同至少包含：

- 标签页类型
- 商品范围或 `productKey`
- 买卖方向
- 状态
- 时间范围
- 页码与页大小

建议页大小固定并设置服务端上限，避免一次返回全历史。

## 7. 安全与一致性要求

- 所有历史查询按服务端认证玩家过滤。
- 撤单使用 `orderId + 所有权校验 + 状态/版本复核`。
- 所有写操作继续使用唯一 `requestId` 并保证幂等。
- 客户端显示的预计返还、价格和数量不作为结算依据。
- 服务端不得把原始数据库异常发送给客户端。
- 部分成交后撤单只能处理剩余量，不能回滚已经成交的资产。
- 快照晚到不能覆盖更新后的订单状态或重复触发泡泡。
- 普通业务拒绝记录为稳定失败，不得误升级为 `RECOVERY_REQUIRED`。

## 8. 推荐实施顺序

### Phase 1：可靠动作回执

- 新增独立 `MarketActionResult` 合同。
- 实现终端内右上角泡泡队列和去重。
- 建立服务端原因码到中文安全文案的映射。
- 增加最近操作记录入口。

### Phase 2：快速撤单与订单资产中心

- 商品详情第三按钮固定为 `撤单`，实现当前商品活动委托弹窗。
- 实现当前委托、成交记录、资产与交付、历史查询四个标签。
- 实现全部商品/当前商品、方向、状态和时间筛选。
- 实现服务端分页与具体订单撤单。

### Phase 3：联动与收口

- 泡泡中的 `查看订单` 跳转到订单与资产中心的对应记录。
- 下单、部分成交、成交、撤单和交付状态实时刷新。
- 收口空态、窄尺寸、重复响应和竞态测试。
- 补齐管理员审计与玩家历史之间的 `requestId / orderId` 定位链。

## 9. 验收标准

- 买入或卖出后，终端右上角可靠显示成功、警告或失败结果。
- 玩家离开泡泡后仍能在操作记录中找到刚才的结果。
- 商品详情固定显示 `买入 / 卖出 / 撤单`；撤单弹窗只显示当前商品可撤活动委托。
- 订单与资产中心可查看全部商品，也可只筛选当前商品的买单或卖单。
- 市场与仓库入口打开同一个中心，并分别默认聚焦当前委托与资产交付。
- 历史查询是辅助视图，不替代当前委托管理和即时动作回执。
- 玩家能看到订单是否挂单、部分成交、完成或撤销。
- 每次撤单都有明确目标，且只撤销服务端确认的剩余量。
- 所有失败均显示安全、明确、可追溯的原因，不出现原始内部异常。

## 10. 实施状态与 2026-08-15 修订说明

2026-08-12 已实现的独立个人市场历史视图、服务端筛选分页和精确撤单主链继续保留：

- 服务端按当前登录玩家读取跨商品订单，不接收客户端提交的账户身份。
- 历史视图支持全部商品/本商品、买单/卖单、进行中/已成交/已结束以及时间范围筛选。
- 撤单只挂在具体且仍可撤销的订单行上，并继续走既有的服务端所有权与状态校验。
- 交易动作结果通过终端内部右上角通知展示；同一请求序列只展示一次，内部数据库异常会转换为安全文案。
- 原“买入 / 卖出 / 历史”详情按钮合同已被本次修订取代。后续实现应改为“买入 / 卖出 / 撤单”，并将现有历史视图升级为跨商品的订单与资产中心。

历史查询现已按本文第 6.2 节落实为完整的服务端筛选分页合同：客户端只提交筛选条件、页码和页大小，服务端始终使用当前认证玩家解析账户身份，并在数据库查询阶段应用商品范围、方向、状态和时间条件。撤单成功后的刷新继续保留当前筛选与页码上下文。

尚未完成的新增工作包括：当前商品活动委托弹窗、市场/仓库双入口、账户摘要带、资产与交付标签，以及详情第三按钮从历史改为撤单。本文描述的是目标合同，不应把这些新增项误报为已完成。

本轮验证覆盖筛选 payload、交易默认值补全过程、历史撤单上下文和历史分页元数据网络往返。交易与历史页面仍共享既有快照主链，没有引入第二套客户端订单真相。
