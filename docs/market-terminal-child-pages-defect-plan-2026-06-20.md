# 市场终端子页面缺陷记录与三轮整改计划

日期：2026-06-20

这份文档记录当前实机截图中已经确认的市场终端缺陷，并把后续至少三轮对话内的整改顺序固定下来。目标是避免继续做零散 UI patch，而是按“先结构、再数据表达、最后统一收口”的方式把 `MARKET`、`MARKET_STANDARDIZED`、`MARKET_CUSTOM`、`MARKET_EXCHANGE` 推向效果图方向。

## 1. 当前对图结论

总入口已经比早期说明页好很多，但三个子页面仍然没有达到效果图里的工作台形态。

当前最主要的问题不是图标缺失，而是：

- 子页面仍然像通用终端 section 拼接结果，而不是市场专用工作台
- 文字、按钮、卡片和滚动区没有形成稳定栅格
- 空数据状态没有专业表达，导致页面像“没填完的调试页”
- 部分内容和按钮仍会挤出或贴近终端边界
- 三类市场的业务语义没有在页面结构上被明确区分

## 2. 已发现缺陷清单

### 2.1 MARKET 总入口

当前状态：

- 三个市场入口已经能同排展示，方向正确
- 下方共享状态和市场说明已经开始向效果图靠拢

明显缺陷：

- 三张入口卡的描述、状态文本和 CTA 仍有重叠风险
- 底部自动刷新文字与共享状态内容仍可能互相挤压
- 卡片内部纵向布局过松，实际可用内容区域被浪费
- 总入口还缺少明确的“卡片顶部图标 / 标题 / 副标题 / CTA / 状态脚注”固定结构

### 2.2 MARKET_STANDARDIZED 标准商品市场

当前状态：

- 页面已尝试做商品、详情、交易动作三栏
- 存入、限价买卖、即时买卖、订单、CLAIMABLE 等业务概念仍存在

明显缺陷：

- 整体结构仍是三块独立大竖栏，不像效果图的“左商品浏览器 + 右侧一体化交易工作台”
- 左侧商品栏混入了大号返回按钮和状态说明，弱化了商品列表的主职责
- 中栏行情与个人状态过于松散，缺少效果图里紧凑的商品摘要、盘口、成交、状态卡片组合
- 右侧动作栏像表单堆叠，按钮和输入框在部分尺寸下拥挤或重叠
- 页面标题和说明仍占用过多首屏高度
- 商品列表实际为空时，空态不够专业，容易被误解为 UI 没做好

后端/数据缺口：

- 当前实机显示 `共 0 项`，说明标准商品目录或可展示商品快照没有填充到终端
- 参考价、买一、卖一、24H、订单簿深度等行情字段为空或为 0，无法呈现效果图中的真实交易密度
- 商品图标、标准化单位和目录来源可以后续增强，但不是本轮结构阻塞点

### 2.3 MARKET_CUSTOM 定制商品市场

当前状态：

- 已有 listing-first 的方向雏形
- 左侧列表、右侧详情/动作已经有初步分区

明显缺陷：

- 左侧挂牌列表仍是大块空占位，不像效果图中的搜索栏、筛选按钮和紧凑 listing 行
- 右侧详情没有形成稳定商品卡，缺少卖家、价格、状态、有效期、领取/取消/购买动作的清晰层级
- 底部动作按钮存在贴边、跨区、视觉漂浮的问题
- 空列表状态占据过多主区域，应该变成可读的空态卡，而不是多条空骨架行

后端/数据缺口：

- 如果当前没有 active custom listings，UI 只能展示空态；要接近效果图，需要测试数据或真实挂牌记录
- 效果图需要结构化字段：物品名、数量、卖家、价格、状态、有效期、可能的卖家信誉；当前终端模型如果只有文本摘要，需要补模型字段或先做降级展示

### 2.4 MARKET_EXCHANGE 汇率市场

当前状态：

- 已有 quote-first 的方向雏形
- 能识别部分手持物品信息，例如实机中出现过 `Quest Book`

明显缺陷：

- 左侧没有形成效果图里的兑换参数区：目标资产、来源资产、兑换方向、我的余额
- 右侧没有形成效果图里的当前汇率卡、规则版本、手续费、更新时间、兑换限制、兑换资产、数量输入和确认按钮
- 当前更像普通文本说明和单个报价按钮，缺少正式 quote 工作台结构
- 底部按钮和右侧面板边界在部分尺寸下仍显得漂浮或贴边

后端/数据缺口：

- 当前没有稳定展示目标资产列表、来源资产列表、方向选择和完整 quote 状态
- 汇率、手续费、限额、更新时间、资产余额等数据需要从服务端 snapshot 稳定提供；如果已有字段但未填充，应先查服务端数据链
- 输入数量与确认兑换需要明确 disabled reason，避免只显示不可点击按钮

## 3. 三轮整改计划

### Round 1：市场子页面结构重排与边界收口

目标：

- 先解决“页面看起来不是效果图结构”的问题
- 不扩业务、不加新后端字段
- 所有内容必须在终端边界内，禁止靠外层滚动硬兜底

范围：

- `MARKET` 总入口：
  - 固定三张入口卡内部结构
  - 修复 CTA 与描述/状态重叠
  - 修复共享状态和自动刷新脚注挤压
- `MARKET_STANDARDIZED`：
  - 从三独立竖栏改成“左商品浏览器 + 右一体化交易工作台”
  - 返回 MARKET 降级为小型导航按钮，不再占据商品列表主位置
  - 右侧工作台按“商品摘要 / 行情盘口 / 个人状态 / 动作条”重新排布
- `MARKET_CUSTOM`：
  - 固定为“左挂牌浏览器 + 右挂牌详情与动作”
  - 空态改成专业空态卡
- `MARKET_EXCHANGE`：
  - 固定为“左兑换参数 + 右报价详情与确认”
  - 避免底部按钮跨出面板

验收标准：

- 460 左右逻辑宽度下不越界、不重叠
- 终端底部仍能看到物品栏
- 每个子页第一眼能看出自己是哪类工作台
- 说明文字只作为辅助，不再占据主工作区
- 完成后必须部署到 `lobby,client` 供人工实机确认

### Round 2：空态、数据映射与后端缺口识别

目标：

- 把“后端没数据”和“UI 没做好”严格分开
- 让空市场也像正式产品，而不是调试页

范围：

- 标准商品市场：
  - 检查商品目录为什么实机为 `0 项`
  - 明确是目录未初始化、服务器数据为空、玩家手持未命中，还是 snapshot 未映射
  - 如果后端已有字段，修复终端映射；如果后端确实无数据，页面展示明确空态与下一步提示
- 定制商品市场：
  - 检查 active listing 数据来源
  - 区分“没有挂牌”和“模型字段不够结构化”
  - 对空 listing 做正式空态
- 汇率市场：
  - 检查 quote target/source/rate/limit/balance 字段链路
  - 明确当前 `Quest Book` 识别后为什么没有形成完整报价
  - 对未选择标的、不可报价、规则未命中分别显示不同状态

验收标准：

- 空数据不再导致页面大面积空白或假骨架
- 每个 disabled action 都能说明原因
- 能列出哪些效果图内容当前已有数据支撑，哪些必须后端补字段或补初始化数据
- 不为了好看伪造真实行情、真实余额、真实订单

执行记录：

- 标准商品市场目录来源已核清：终端快照会从玩家手持可标准化物品、活跃订单商品、成交记录商品、玩家个人订单商品、玩家 custody 商品里合并 `productKeys`。因此实机 `共 0 项` 不等于 UI 没接线，而是当前没有任何可发现标准商品源；页面需要展示正式空态，不应伪造商品或行情。
- 标准商品市场行情来源已核清：参考价来自最近成交；买一/卖一来自开放买卖单；24h 来自近 24 小时成交；AVAILABLE/ESCROW/CLAIMABLE/冻结资金来自 custody 与个人订单。当前这些为空时应显示“未选商品/无盘口/无资产”的状态原因，而不是让交易动作看起来可继续。
- 定制商品市场数据来源已核清：全部挂牌来自 `browseListings`，我的出售来自 `listSellerActiveListings`，待处理来自买家待领取与卖家待交付合并结果。服务端为网络传输会用固定长度数组补空字符串，客户端之前把这些 padding 当成可显示列表项，造成大量假空行；本轮已在 viewmodel 侧过滤 padding，并补充“当前范围没有挂牌数据”的禁用原因。
- 汇率市场数据来源已核清：当前只有 `task-coin-formal` 一个正式兑换标的；正式 quote 需要服务端玩家上下文、手持任务书硬币、汇率服务可用，并通过 `previewHeldCoinFormal` 取得 pair/rule/limit/rate 等字段。未选择标的、无手持物品、服务不可用、规则禁兑都应展示为不同不可执行原因；本轮已在 viewmodel/UI 层明确 disabled reason。
- 本轮不新增真实行情、余额、订单或 listing 字段；效果图里的图标、卖家信誉、列表搜索筛选、更多行情密度属于后续 Round 3 或后端字段扩展范围。

### Round 3：视觉密度、交互动作与统一验收

目标：

- 在结构和数据边界清楚后，做视觉密度与操作链最终收口
- 让三类市场虽然业务不同，但都像同一个终端系统下的正式页面

范围：

- 统一字体层级、面板间距、按钮高度、滚动条位置
- 标准商品市场：
  - 商品浏览行、盘口列、最新成交、个人状态卡、动作按钮统一收紧
  - 买入/卖出/存入/领取/撤单动作保持 popup 确认链
- 定制商品市场：
  - listing 行、详情卡、购买/取消/领取动作统一收紧
- 汇率市场：
  - quote 卡、规则/费率/限额卡、输入与确认按钮统一收紧
- 帮助浮层统一承接长说明
- 补充或收紧布局测试，重点测稳定外框、内部滚动边界和按钮不越界

验收标准：

- 对照效果图，三类市场都达到“可接受的成品方向”，即使暂时没有图标
- 常用 GUI scale 下不出现文字压按钮、按钮出界、滚动条贴错边
- 执行动作后 snapshot/feedback 不破坏布局
- 完成后构建、部署，并由人工在游戏内确认

## 4. 下一轮执行原则

- 先做 Round 1，不要同时扩仓库、企业、公用市场制度
- 不要用更多说明文本掩盖页面结构问题
- 不要把后端缺数据伪装成真实行情
- 需要人工确认 UI 时，必须先用脚本完成构建与部署
- 每轮完成后更新 `docs/WORKLOG.md`
