# 市场终端效果图差异复盘

日期：2026-06-21

本文档记录本轮对比结论：参考效果图为 `/home/u24/图片/市场.png`。用户提到的 `/home/u24/图片/市场.jpg` 当前未在本机发现；本轮以同目录下已经存在、并与对话中效果图一致的 `市场.png` 为基准。

对比对象为 2026-06-21 对话中的四张实机截图：

- `MARKET` 市场总入口
- `MARKET_STANDARDIZED` 标准商品市场
- `MARKET_CUSTOM` 定制商品市场
- `MARKET_EXCHANGE` 汇率市场

## 1. 总体结论

当前终端壳层、深色配色、圆角方向和 MARKET 总入口已经明显接近效果图，但三个子页面仍然没有真正进入效果图的工作台形态。

核心差距不是单个按钮、颜色或文案，而是：

- 子页面仍保留较多旧式表单/说明页结构
- 交易工作流没有被压缩进效果图那种高密度卡片和底部动作条
- 商品、listing、汇率等核心对象缺少真实图标和结构化摘要
- 部分区域仍依赖长文本和滚动，而效果图主要靠固定区域承载关键信息
- 标准商品市场仍有右侧动作区越界风险，是当前最严重的可见布局问题

后续应避免继续做零碎 UI patch，而要按页面类型重构为专用 market workbench。

## 2. MARKET 总入口差异

当前状态：

- 三个市场入口卡已经同屏展示，方向正确
- 深色主题、圆角面板、左侧图标导航和右上角图标按钮已经接近目标
- 底部共享状态和规则提示已经从说明页转向入口页

与效果图差异：

- 入口卡内部仍偏空，图标的体积和质感不如效果图中的箱子、木箱、金币堆清晰
- 卡片说明文字仍偏多，效果图更像“标题 + 极短副标题 + 关键状态 + CTA”
- 规则提示区仍可以继续压缩，页面操作说明应减少，只保留制度/交易规则提示
- 导航图标已存在，但形状仍不够稳定，部分小尺寸下会糊成抽象块
- 顶栏按钮虽然已是图标，但还需要保证全部受 title bar 容器高度约束，不得越过顶栏

应保留的方向：

- MARKET 总入口继续作为“去哪一个市场”的主入口
- 帮助内容继续放到帮助弹层或规则提示，不再抢主入口区域
- 自动刷新等页面机制说明不应作为主文案出现

## 3. MARKET_STANDARDIZED 标准商品市场差异

当前状态：

- 已经尝试拆成商品浏览、商品详情、交易动作三块
- 标准市场业务动作仍在：存入、限价买卖、即时买卖、订单、CLAIMABLE
- 真实物品图标链路已有初步实现，但在空数据或部分字段缺失时仍退化为占位感很强的图形

严重差异：

- 右侧交易动作区在实机截图中明显超出终端右边界，这是布局硬错误
- 当前还是“三个大竖栏”思路，效果图是“左侧商品浏览器 + 右侧一体化交易工作台”
- 商品浏览缺少搜索框、筛选按钮、紧凑商品行、真实物品图标、库存/价格/在售数量
- 商品详情区没有形成主视觉，效果图中应有物品图标、名称、参考价、24H 成交量
- 买盘、最新成交、卖盘没有做成紧凑三列行情表
- 可用库存、可领取资产、我的订单没有形成底部状态卡组
- 交易动作不应占独立高竖栏，应压缩为底部彩色动作按钮组
- 当前空数据状态仍像调试页，效果图即使无数据也应显示稳定的 browser/dashboard 框架

需要重构的目标结构：

- 左栏：商品浏览器
  - 搜索框
  - 筛选按钮
  - 商品列表行
  - 页码/数量
- 右上：商品摘要
  - 真实物品图标
  - 商品名
  - 参考价
  - 24H 成交量
- 右中：行情面板
  - 买单
  - 最新成交
  - 卖单
- 右下：个人状态与动作条
  - 可用库存
  - 可领取资产
  - 我的订单
  - 即时买入、即时卖出、买类挂牌、下架挂牌、领取、刷新报价

可能的后端/数据缺口：

- 当前标准商品目录可能为空，导致列表无法接近效果图的商品密度
- 参考价、24H 成交量、买一卖一、订单簿深度依赖成交和订单数据
- 真实物品图标必须优先用客户端 `ItemStack` 渲染；无法解析时才能用 fallback badge

## 4. MARKET_CUSTOM 定制商品市场差异

当前状态：

- 页面边界相对标准市场更稳定
- 已形成左列表、右详情/动作的基本方向
- 空数据情况下不会像早期那样明显出界

与效果图差异：

- 左侧挂牌列表应是搜索/筛选 + 紧凑 listing 行，而不是大块空态和长文本
- listing 行应包含真实物品图标、物品名、数量、卖家、价格
- 右侧商品详情应是商品卡，而不是字段说明集合
- 效果图中右侧应突出大物品图标、商品名、卖家、信用/评价、价格、描述、状态、有效期
- 购买、取消订单、领取商品、联系卖家应作为固定底部动作条出现
- 空数据状态应保留正式列表框架，但不能用大面积骨架行制造“未完成 UI”的观感

需要重构的目标结构：

- 左栏：定制商品列表
  - 搜索输入
  - 筛选按钮
  - listing 行：图标、名称、数量、卖家、价格
  - 页码/总数
- 右栏：listing 详情
  - 大物品图标
  - 商品名
  - 卖家/信誉
  - 价格
  - 描述
  - 状态/有效期
  - 底部动作按钮

可能的后端/数据缺口：

- 当前如果没有 active custom listings，只能展示正式空态
- 卖家头像、信誉、评价、有效期等可能需要模型字段补齐
- 没有这些字段时，UI 应保留位置并显示降级文本，不应改回长说明页

## 5. MARKET_EXCHANGE 汇率市场差异

当前状态：

- 已经是左右两栏
- 能识别部分手持输入资产，例如 `Quest Book`
- 右侧有目标资产/货币图标方向

与效果图差异：

- 左栏没有形成正式的兑换参数区
- 右栏没有形成正式的汇率仪表盘
- 当前仍以长文本状态为主，效果图是卡片化指标和输入控件
- 兑换数量输入、资产下拉、估算结果和确认按钮没有形成一组稳定表单
- 规则版本、手续费、更新时间、兑换限制、资产余额没有做成独立指标卡
- 当前状态文本过多，玩家需要读说明才能理解；效果图是一眼看出“换什么、按什么价、手续费多少、能换多少”

需要重构的目标结构：

- 左栏：选择兑换对
  - 目标资产下拉
  - 来源资产下拉
  - 我的余额
  - 兑换方向
- 右栏：当前汇率
  - 大号汇率公式
  - 规则版本
  - 手续费
  - 更新时间
  - 刷新按钮
  - 最小/最大兑换
  - 兑换资产
  - 数量输入
  - 估算结果
  - 确认兑换按钮

可能的后端/数据缺口：

- rule version、fee、updatedAt、min/max、账户资产余额如果没有稳定字段，需要补 snapshot 或先用结构化占位
- formal quote 的可执行状态需要明确 disabled reason，不能只显示不可点击按钮
- 手持物品识别成功后，应显示输入资产图标和 item id，但不应让 item id 变成主视觉

## 6. 跨页面共性缺陷

### 6.1 布局与容器

- 当前部分面板仍像手写绝对坐标，没有形成稳定 container/box 约束
- 顶栏按钮、右侧动作区、底部按钮等必须以父容器高度/宽度为上限计算
- 非列表区不应滚动；列表区可以滚动，但滚动条必须在对应面板内部
- 子页面需要固定“浏览区 + 详情区 + 动作区”的边界，不允许内容扩出终端外层

### 6.2 信息密度

- 文字字号、行高、面板 padding 仍偏大，导致同样面积显示的信息少于效果图
- 当前仍有说明文字占据核心区域，效果图更重视对象、指标、动作
- 低价值文案应删除，例如“列表每 30 秒自动刷新”“先选市场类型”这类页面操作说明

### 6.3 图标与视觉锚点

- 终端导航图标需要继续打磨，避免小尺寸糊成一坨
- 市场入口图标应更接近效果图的箱子、木箱、金币堆
- 商品、listing、汇率输入资产必须优先使用真实 Minecraft item 渲染
- fallback 图标只应在真实物品无法解析时使用

### 6.4 动作层级

- 交易动作应按工作流聚合成固定 action bar 或按钮组
- Disabled 状态必须解释原因，但原因不应占据大块主区域
- 帮助/说明应走顶栏帮助或局部提示，不应回到说明页结构

## 7. 建议的后续执行顺序

### Step 1：先修标准商品市场越界和架构

优先级最高。标准市场目前最不符合效果图，也是最容易暴露交易系统核心能力的页面。

目标：

- 左栏只做商品浏览器
- 右侧整合成行情、状态、动作工作台
- 去掉独立高竖交易动作栏
- 所有动作按钮收到底部动作条

### Step 2：抽共享市场工作台组件

不要再让三个子页面各自拼手写坐标。

建议抽象：

- `MarketBrowserRow`
- `MarketSearchBar`
- `MarketHeroCard`
- `MarketMetricCard`
- `MarketActionBar`
- `MarketOrderBookPanel`
- `MarketAssetPairPanel`

### Step 3：定制市场和汇率市场套同一视觉语法

标准市场结构稳定后，再把 custom 和 exchange 套入相同视觉体系：

- custom：listing browser + listing detail + action bar
- exchange：pair selector + rate dashboard + quote form/action bar

### Step 4：补真实数据字段与降级策略

最后明确哪些效果图内容可以由当前后端提供，哪些必须补字段。

原则：

- 不伪造真实行情、余额、订单、挂牌
- 可以做结构化占位
- 空数据也必须像正式页面

## 8. 本轮验收基准

下一轮 UI 改造至少满足：

- 标准商品市场不再有右侧越界
- 三个子页面都不再是说明页或通用表单堆叠
- 非列表核心区域无需滚动即可看完
- 列表区可以滚动，但滚动条必须只在列表面板内部
- MARKET 总入口保留当前整体方向，只继续减少低价值说明和打磨图标
- 所有市场页都能在同一终端壳层内呈现统一的深色圆角卡片风格
