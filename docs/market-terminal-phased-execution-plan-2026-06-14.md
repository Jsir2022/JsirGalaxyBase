# 市场终端分阶段执行计划

日期：2026-06-14

这份文档用于把当前已经确认的市场终端方向，收口成可执行、可验收、可追溯的阶段计划。

它主要解决三个问题：

1. 市场终端为什么不能再按“说明页 + 堆字段”继续演化
2. 为什么不应把四个页面机械地拆成四个完全独立阶段
3. 后续开发应按什么顺序推进，才能既保住业务边界，又逐步做出成品级终端

## 1. 当前已确认的产品前提

当前关于市场终端，已经明确成立的前提有：

- `MARKET` 是三类市场的总入口，不是混合交易详情页
- 市场必须严格分为：
  - `标准商品市场`
  - `定制商品市场`
  - `汇率市场`
- 三类市场共享基础设施，但不共享核心交易模型
- 标准商品市场是当前最接近核心玩法主链的一页
- 定制商品市场应坚持 `listing-first`
- 汇率市场应坚持 `quote-first`
- 说明文案可以存在，但应通过帮助浮层、风险提示、辅助卡片承接，而不是把主页面做成说明书

## 2. 为什么不按“四页 = 四阶段”硬拆

如果直接把：

- MARKET 总入口
- 标准商品市场
- 定制商品市场
- 汇率市场

机械拆成四个互不相干的阶段，会出现两个问题：

### 2.1 共享壳层会反复重做

这四页并不是四个完全独立应用。

它们共享很多终端层责任：

- 顶栏上下文
- 左侧导航
- 帮助浮层
- 内部滚动边界
- 状态反馈
- 弹窗确认
- snapshot 刷新
- 银行余额 / 冻结资金联动
- disabled reason 与 warning/error 语义

如果一页一页各自闭门处理，后面很容易每页都长出一套自己的壳层风格。

### 2.2 标准商品市场的成熟度显著高于另外两页

当前真实实现中：

- 标准商品市场已有最完整的交易主链
- 定制商品市场需要重点收口对象浏览和挂单交付节奏
- 汇率市场需要重点收口报价、规则、限额与执行节奏

也就是说，后两页还不适合和标准商品市场被当成同难度、同成熟度页面来推进。

所以正确拆法不是：

- `四页 = 四阶段`

而应是：

- `共享市场壳`
- `核心工作台页`
- `补齐另外两类市场页`
- `统一收口`

## 3. 正式阶段拆分

当前建议采用 5 个阶段。

---

## Phase 1：市场共享壳与 MARKET 总入口

### 目标

先把“市场终端不是说明页”这件事做对，并建立三类市场共享的终端骨架。

### 核心范围

- MARKET 根页只保留：
  - 三类市场入口
  - 极简共享状态摘要
  - 轻量帮助入口
- 顶栏上下文收口：
  - 当前页
  - 当前玩家/终端上下文
  - 贡献 / 小型功能按钮
- 页面主体结构收口：
  - 不再出现大段说明正文
  - 不再把标准商品、定制商品、汇率市场数据混排在根页
- 建立统一的页面级帮助与说明承载方式：
  - 帮助浮层
  - 风险提示
  - 小型辅助卡

### 明确不做

- 不在 MARKET 根页执行真实交易动作
- 不把订单簿、挂牌详情、汇率报价堆回根页
- 不在这一阶段重做三类子页全部细节

### 产出物

- 成品化 MARKET 总入口页
- 市场共享壳层约定
- 统一帮助浮层入口

### 验收标准

- 首屏能完整看到三个入口
- 根页不再像说明书
- 所有内容都在终端边界内
- 不出现入口按钮被挤出页面的问题
- 顶栏信息不再长到影响主体操作

---

## Phase 2：标准商品市场工作台

### 目标

把 `MARKET_STANDARDIZED` 做成市场终端的第一张核心工作页。

### 为什么它优先

因为它目前最接近整个玩法内核：

- 商品目录
- 市场托管仓
- 订单簿
- 即时成交
- 我的订单
- CLAIMABLE
- 银行结算联动

后续仓库、企业经营、公共采购等制度，也最容易先挂在这条链上。

### 核心范围

- 商品浏览区
  - 目录化商品列表
  - 当前选中商品
  - 活跃/可交易对象优先展示
- 商品详情区
  - 商品名、单位、目录来源、准入信息
  - 最新成交、买一/卖一、基础深度
- 动作区
  - 存入仓储
  - 限价买单
  - 限价卖单
  - 即时买入
  - 即时卖出
- 个人状态区
  - AVAILABLE
  - ESCROW
  - CLAIMABLE
  - 冻结资金
  - 我的订单
- 确认与反馈链
  - popup 确认
  - snapshot 回写
  - 银行余额同步
  - warning/error 语义完整

### 明确不做

- 不借这轮去实现企业仓 / 公共仓
- 不把定制商品市场逻辑塞进标准商品市场
- 不把汇率市场逻辑塞进标准商品详情页

### 产出物

- 标准商品市场主工作台页
- 可稳定执行的主要交易动作链
- 与银行 / 市场仓状态联动的页面反馈

### 验收标准

- 玩家能顺手完成“选商品 -> 看详情 -> 下单/成交 -> 看结果”
- 页面主次关系清楚，先是商品，再是详情，再是动作
- `AVAILABLE / ESCROW / CLAIMABLE / 冻结资金` 可读
- 动作完成后 snapshot 不落后一拍
- 部分成交、撤单失败、深度不足等反馈语义不含混

---

## Phase 3：定制商品市场工作台

### 目标

把 `MARKET_CUSTOM` 正式收口成 `listing-first` 的单件挂牌工作页。

### 核心范围

- 挂牌列表区
  - 单件商品浏览
  - 当前范围切换
  - 我的挂牌 / 可购买 / pending 等视图
- 挂牌详情区
  - 物品快照
  - 卖家 / 买家
  - 价格
  - 状态
  - 交付语义
- 动作区
  - buy
  - cancel
  - claim
- 记录与提示区
  - 待领取 / 待完结状态
  - 交付风险提示
  - 审计/留痕摘要

### 明确不做

- 不出现订单簿
- 不出现标准商品仓储 AVAILABLE/CLAIMABLE 语义
- 不把定制商品页强行长成标准商品页翻版

### 产出物

- listing-first 的定制商品市场页
- 单件物品详情与动作闭环

### 验收标准

- 玩家是先看挂牌，再看详情，而不是先看说明
- buy / cancel / claim 语义明确
- 待领取 / 待交付链与标准商品 CLAIMABLE 不混
- 页面的对象感是“单件挂牌”，不是“商品盘口”

---

## Phase 4：汇率市场工作台

### 目标

把 `MARKET_EXCHANGE` 正式收口成 `quote-first` 的兑换工作页。

### 核心范围

- 兑换对 / 标的浏览区
- 当前报价区
- 规则版本与来源区
- 费率 / 限额 / 风控说明区
- 手持资产摘要区
- 动作区
  - refresh quote
  - confirm exchange

### 明确不做

- 不复用商品目录
- 不复用商品订单簿
- 不复用商品仓储状态块
- 不把兑换页写成“另一种商品买卖页”

### 产出物

- quote-first 的汇率市场页
- 报价刷新与确认兑换闭环

### 验收标准

- 玩家先看到的是“能换什么、按什么规则换”
- refresh / confirm / execute 节奏明确
- 费率、限额、规则版本可读
- 页面不再出现标准商品仓储与 CLAIMABLE 语义

---

## Phase 5：跨页统一收口

### 目标

在三类市场页都进入可用状态后，做一次统一产品化收口。

### 核心范围

- 顶栏长度与上下文统一
- 小型帮助入口统一
- popup 确认语义统一
- 通知/warning/error 语义统一
- disabled reason 统一
- 滚动区与内容边界统一
- 银行余额、冻结资金、资产状态的联动刷新统一
- 空状态 / 无数据 / 不可用状态统一

### 这一阶段的重点

不是加新功能，而是让市场终端从“几张功能页”变成“一套像同一个产品做出来的系统”。

### 验收标准

- 四页看起来属于同一套终端产品
- 没有一页继续像说明书
- 没有一页继续像技术测试面板
- 所有页面都能稳定在终端边界内滚动和操作

## 4. 推荐执行顺序与优先级

推荐顺序：

1. Phase 1：MARKET 总入口
2. Phase 2：标准商品市场
3. Phase 3：定制商品市场
4. Phase 4：汇率市场
5. Phase 5：统一收口

其中实际优先级应理解为：

- **最高优先级**：Phase 1 + Phase 2
- **第二优先级**：Phase 3
- **第三优先级**：Phase 4
- **最后统一收口**：Phase 5

原因很明确：

- 根页先做对，后续不再反复返工
- 标准商品市场最接近玩法核心，应先打磨成“真工作台”
- 定制商品和汇率市场需要在边界清楚的前提下推进

## 5. 每个阶段的交付要求

每个阶段完成时，建议都至少补齐下面四类内容：

1. `代码改动`
2. `定向测试 / 构建验证`
3. `WORKLOG 记录`
4. `人工验收要点`

这能保证后续继续交给另一个 AI 实作时，不会只留下截图印象，而是能明确知道：

- 这一阶段到底改了什么
- 哪些属于已成立能力
- 哪些问题还留给下一阶段

## 6. 当前结论

当前市场终端的正确推进方式，不是把四页平均摊开做，也不是继续先调局部 spacing。

正确路线应是：

- 先收口共享市场壳
- 先做扎实标准商品市场
- 再分开补定制商品市场与汇率市场
- 最后统一做跨页收口

如果后续执行还能始终稳定回答下面三个问题，就说明阶段计划没有跑偏：

1. 当前页面是在服务哪一类市场
2. 当前页面最重要的玩家动作是什么
3. 当前页面有没有重新退化成说明页或混合大桶页

如果答不清，就说明阶段边界已经开始松动。
