日期：2026-08-08

## 1. 基准与范围

本文档以 `/home/u24/图片/市场第三版.png` 为标准商品市场的最新、唯一视觉目标，
对比 2026-08-08 对话中提供的三张实机图：

1. 标准商品市场浏览页
2. 商品 Hover 行情浮层
3. 标准商品交易详情页

本文最初用于记录差异和验收口径；2026-08-08 已按 P0-P3 实施第一轮运行时代码、
数据库读取索引和终端交互整改，并在末尾追加当前实施状态。旧效果图和旧市场说明

## 2. 总体判断

当前实现已经完成以下基础，不应在后续整改中推倒：

- 深色终端壳、顶部状态栏、左侧图标导航和圆角边界方向正确。
- 标准市场已经具备四列浏览、真实 ItemStack 图标、Hover 和独立详情路由。
- 浏览、Hover、详情三段式交互已经可辨认，不再是说明页或常驻三栏表单。
- 页面主体没有明显越出终端外框，物品栏仍可见。

但当前版本仍属于“目录骨架 + 旧交易详情”的过渡态，距离目标主要有四类差距：

- **浏览信息密度不足**：当前每页仅 8 项，商品卡过大，缺少涨跌幅、迷你走势和流动性信号。
- **Hover 不是比较工具**：浮层面积过大、遮挡过多，且缺少真实行情时只剩大块空白。
- **详情不是现代交易工作台**：没有价格图、成交量、时间范围、结构化深度和订单票据。
- **玩家流程仍暴露内部托管状态**：`AVAILABLE`、`CLAIMABLE`、存入、领取仍作为主操作，
  与账户仓自动预留、自动交付的长期方向冲突。

## 3. 浏览页差异

### 3.1 当前实机状态

- 已有四列，但只有两行，共 8 个商品。
- 商品卡显示真实图标、英文名、参考价和“可交易/已选中”。
- 商品名发生明显截断，例如 `Iron In`、`Gold In`、`Aluminiu`。
- 搜索栏、服务在线文本、筛选按钮和底部分页均已存在。
- 第二行下方存在大面积无信息空白。

### 3.2 与目标图的差距

| 项目 | 最新目标 | 当前实机 | 差距类型 |
| --- | --- | --- | --- |
| 网格密度 | 固定 4 列 x 3 行，首屏 12 项 | 4 列 x 2 行，首屏 8 项 | UI 布局 |
| 商品名称 | 中文正式展示名，单行完整或专业截断 | 英文名截断且语义不完整 | 数据 + UI |
| 价格信息 | 最新/参考价 + 涨跌百分比 | 只有参考价 | 行情数据 |
| 趋势表达 | 每卡固定迷你价格线 | 无 | 行情数据 + 绘制 |
| 流动性 | 底部小型状态点 | 仅“可交易”文字 | UI 映射 |
| 筛选区 | 搜索、过滤、范围、排序、页码均为紧凑控件 | 搜索 + 服务文本 + 大号筛选按钮 | UI 交互 |
| 分页 | 明确页码，可直接切页 | 仅上一页/下一页和 `1/1` | UI + payload |
| 空间利用 | 卡片填满可用浏览区 | 网格下方大面积留空 | UI 布局 |

### 3.3 浏览页收口标准

- 目标终端尺寸下必须首屏显示 `4 x 3` 张商品卡；只有网格可以滚动。
- 搜索、过滤、排序和分页固定在网格外，不随滚轮移动。
- 商品卡固定包含：真实图标、正式展示名、最新或参考价、周期涨跌、迷你走势、
  流动性状态。
- 商品名最多一行；空间不足时做带省略号的专业截断，完整名称由 Hover 展示，
  不允许直接截成无意义字符串。
- 上涨使用绿色、下跌使用红色，遵循最新效果图的美股终端语义。
- 无成交数据时不伪造涨跌和折线，显示中性 `暂无成交`，但卡片尺寸不得变化。
- “服务在线”属于全局状态，不应占据商品筛选工具栏的主要宽度。

## 4. Hover 行情浮层差异

### 4.1 当前实机状态

- Hover 已能关联真实商品并显示图标、名称和参考价。
- 当前浮层位于网格中央，宽高过大，遮挡约四张以上商品卡。
- 最新成交、24h、买一、卖一均为空，图表区域成为大块黑色空面板。
- 有“暂无成交历史”空态，但信息层级松散，不能快速横向比较。

### 4.2 与目标图的差距

| 项目 | 最新目标 | 当前实机 | 差距类型 |
| --- | --- | --- | --- |
| 尺寸 | 紧凑报价卡，仅遮挡邻近少量卡片 | 接近模态窗口尺寸 | UI 布局 |
| 定位 | 贴近当前卡片，按边界自动翻转 | 居中覆盖网格 | Hover 定位 |
| 行情摘要 | 最新价、24h 涨跌、成交量、买一/卖一 | 多数字段为空且无变化语义 | 行情数据 |
| 账户摘要 | 可卖数量、冻结/待交付等关键状态 | 缺失 | 快照数据 |
| 图表 | 有真实点时显示紧凑折线 | 固定大空图表 | 数据 + 绘制 |
| 空态 | 一行明确空态，不改变浮层大小 | 大空图 + 底部空态 | UI 状态 |

### 4.3 Hover 收口标准

- Hover 只在 `BROWSE` 模式出现，不接受点击，也不阻塞网格滚动。
- 宽度不超过内容区约 `35%`，高度不超过内容区约 `60%`；优先显示在指针右下，
  空间不足时向左或向上翻转，并始终夹在终端内容边界内。
- 浮层应尽量只遮挡当前项及相邻 1 到 2 项，不能覆盖网格主体。
- 必须在点击、滚动、刷新、失焦、打开 modal、切换页或进入详情时立即关闭。
- 有至少两个真实成交点才绘制折线；否则用紧凑的 `暂无成交历史` 取代整个图表区。
- Hover 的用途是比较，不提供下单按钮，也不承载长说明。

## 5. 交易详情页差异

### 5.1 当前实机状态

- 顶部已有真实物品图标、商品名、参考价和 24h 摘要。
- 中部仍是“买单 / 最新成交 / 卖单”三个文本块，没有形成结构化深度表。
- 下方显示“可售库存 / 待领取 / 订单与冻结”三张状态卡。
- 底部仍有“存入、即时买、即时卖、买挂单、卖挂单、领取、撤单”旧动作按钮。
- 最新成交区域和 24h 文本出现错位、叠字，状态卡副文案也存在重叠。
- 没有 K 线/价格线、成交量柱、周期切换，也没有可编辑下单票据。

### 5.2 与目标图的差距

| 区域 | 最新目标 | 当前实机 | 差距类型 |
| --- | --- | --- | --- |
| Hero | 图标、名称、最新价、涨跌幅 | 图标、名称、参考价、24h 数字 | 行情数据 + UI |
| 图表 | `1h/24h/7d`、K 线或真实价格线、成交量柱 | 无 | 聚合数据 + 绘制 |
| 盘口 | 多档买盘、最新成交、多档卖盘，价格和数量分列 | 文本句子和占位横线 | 数据适配 + UI |
| 市场统计 | 24h 高低、成交量、成交额 | 无 | 聚合数据 |
| 交易票据 | 买/卖、市场/限价、数量、价格、估值、手续费、余额/库存 | 多个固定动作按钮 | UI + 动作 payload |
| 账户状态 | 可用仓储、当前委托、待收货的紧凑摘要 | 内部 `AVAILABLE/CLAIMABLE` 卡 | 产品语义 |
| 提交动作 | 单一明确的“确认买入/确认卖出” | 七个同级按钮 | UI 工作流 |
| 仓储交割 | 下单时自动预留，成交后自动投递；异常才人工处理 | 手动存入、手动领取 | 交易/仓储主链 |

### 5.3 详情布局收口标准

- 核心详情必须在一个终端首屏内完成，不允许整页滚动。
- 推荐主区宽度预算：行情图约 `40%`，盘口约 `27%`，订单票据约 `33%`；
  允许随实际像素微调，但订单票据不得挤出边界。
- 订单簿和历史委托可局部滚动，Hero、图表周期、账户摘要和确认按钮必须固定。
- 买盘使用绿色，卖盘使用红色，最新成交保持中性；价格和数量严格分列对齐。
- 订单票据必须由控件表达，而非弹出多个含义模糊的动作：
  - `买入 / 卖出` 分段选择
  - `市价 / 限价` 单选
  - 数量输入和“最大”快捷动作
  - 限价模式下的价格输入
  - 预估总额、手续费、可用余额或账户仓可卖量
  - 单一确认 CTA
- 点击盘口价格只能回填票据，不得直接提交订单。
- `AVAILABLE`、`ESCROW`、`CLAIMABLE` 只用于审计和异常详情，不作为玩家首页术语。

## 6. 数据与后端缺口

以下内容不能通过继续调整坐标得到，必须由真实快照或聚合查询支持：

### 6.1 目录批量行情

每个当前目录页商品至少需要：

- `lastPrice` / `referencePrice`
- `changeAmount`、`changePercent`、`changePeriod`
- `bestBidPrice`、`bestBidQuantity`
- `bestAskPrice`、`bestAskQuantity`
- `tradeVolume24h`、`tradeCount24h`
- 迷你走势的真实价格点
- 流动性/停牌/不可交易状态及原因

必须对当前目录页批量读取，禁止在客户端对每个卡片单独发请求。

### 6.2 详情行情聚合

- `1h / 24h / 7d` 的 OHLC bucket、成交量和成交笔数。
- 24h 最高、最低、成交量和成交额。
- 多档买盘、多档卖盘和最近成交，价格与数量必须结构化传输。
- 数据不足时使用真实价格线或明确空态，严禁伪造 K 线。

### 6.3 账户与仓储摘要

- 账户仓对当前商品的可卖数量。
- 银行可用余额和冻结资金。
- 当前委托数量、可撤数量、待收货数量和恢复状态。
- 当前只解析 Base Vault；未来可由授权 AE 仓优先、Base Vault 回退，市场 UI 不感知
  底层仓储来源变化。

### 6.4 下单合同

- 市价/限价、买/卖、数量、限价价格、预估金额、手续费和资产来源/去向。
- 卖单提交时从账户仓自动预留到市场托管；余额或库存变化时服务端重新校验。
- 买入成交后自动投递账户仓；只有满仓或不确定交付才显示恢复操作。
- 所有动作继续使用 request id、服务端确认和审计，客户端计算只用于预览。

## 7. 优先级与整改边界

### P0：先消除当前硬缺陷

- 修复详情页叠字、行高和列宽。
- 缩小 Hover 并恢复邻项比较能力。
- 将浏览网格从 8 项调整为目标首屏 12 项。
- 统一商品正式展示名和截断策略。

### P1：补真实行情浏览

- 批量补齐目录涨跌、成交量、买一卖一和价格点。
- 商品卡加入百分比、迷你走势和流动性点。
- Hover 使用同一批真实数据，不再显示大块空图。

### P2：重构详情交易工作台

- 增加周期图表、成交量、市场统计和结构化盘口。
- 用可编辑订单票据替换七个同级动作按钮。
- 收起内部托管术语，只保留玩家可理解的账户仓、委托和待收货摘要。

### P3：自动仓储交割

- 卖出时从账户仓自动预留，不再要求玩家先“存入”。
- 买入后自动投递账户仓，不再把“领取”作为常规步骤。
- 满仓、版本冲突或交付不确定时继续沿用 durable pending/recovery 语义。

## 10. 2026-08-08 第一轮实施结果

### 已完成

- 标准市场浏览页固定为 `4 x 3` 商品网格；搜索、筛选、排序和分页位于网格外。
- 商品卡接入真实物品图标、最新/参考价、24h 涨跌、真实成交迷你走势、流动性状态，
  并按当前目录页批量读取盘口和成交摘要。
- Hover 使用同一批真实行情，边界翻转、路由切换和弹窗清理沿用共用 Hover 框架；
  不足两个成交点时不绘制大空图。
- 详情页改为横向行情图、盘口、订单票据布局；票据明确买卖方向、市价/限价、数量、
  限价、估值和资产来源，并通过统一确认动作转发到现有撮合链。
- 标准卖出主路径改为从个人 Base Vault 自动预留，买入成交后自动尝试投递 Base Vault；
  满仓或不确定交付继续保留可审计待处理状态。
- 新增标准市场只读聚合仓和 PostgreSQL 读取索引；定制市场、汇率市场业务语义未改。

### 尚未完成，不得在验收中误报

- 客户端已可切换 `1h / 24h / 7d`，并显示对应真实聚合桶的收盘价线与成交量柱；完整
  OHLC 实体/影线尚未进入网络合同，因此当前不能宣称为完整 K 线。
- 筛选和排序当前对服务端返回的目录页生效；尚未成为覆盖完整目录的数据库级排序分页。
- 盘口行尚未支持点击后自动回填价格和数量，订单票据也尚无“最大”快捷按钮。
- 订单票据可展示资产来源和估值，但银行可用余额仍未作为独立结构化字段进入市场快照。

- `git diff --check` 通过。

## 11. 2026-08-08 实机反馈后的第二轮收口

- **日内涨跌口径**：目录卡不再根据任意两个采样点推算涨跌。服务端以
  `Asia/Shanghai` 当日 `00:00` 后第一笔真实成交为开盘价，以最新真实成交为现价，计算并
  传输独立的日内涨跌百分比。当日没有真实成交时显示 `今日暂无成交`，不伪造百分比。
- **紧凑货币表达**：卡片、Hover、盘口与图表统计中的价格省略重复 `STARCOIN` 后缀；
  完整确认弹窗和服务端结算语义不变。
- **浏览卡密度**：商品卡不再绘制迷你走势图，只保留真实图标、价格、日内涨跌和流动性，
  将有限面积留给名称与关键行情。
- **Hover 信息密度**：目标字段固定为最新价、今日涨跌、零点基准、买一/卖一及数量、
  24h 成交量、流动性、账户仓可卖、锁定和待收货。图表改为基于真实成交价格的红绿涨跌柱，
  并显示最高/最低价格及 `00:00 -> 现在` 时间轴；不足两个点时折叠为紧凑空态。
- **详情防叠层**：Hero 和页脚进一步压缩，盘口行收为 `价格 x 数量`。详情图表显示价格、
  成交量和时间坐标，以蓝色真实成交柱表达价格，以红绿柱表达成交量涨跌；买盘、成交、卖盘
  分别使用绿色、中性色和红色。详情正文不再承载价格/数量输入，买入和卖出按钮打开独立订单
  弹窗，撤单保持独立命令。框架层禁止宽高为零的标签继续绘制，并在绘制每行前检查可用高度，
  消除被布局隐藏的文字越界进入相邻卡片的问题。
- **验收重点**：浏览卡应出现正负日内百分比；Hover 应比首轮丰富但仍保持非模态；详情
  的图表、盘口、命令区和三张摘要卡必须首屏无叠字。当前后端只提供真实离散成交点，详情
