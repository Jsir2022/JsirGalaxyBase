# 标准市场自成交未绕过 BUG - 2026-08-18

## 状态

- 状态：已修复并部署；Lobby 已验证启动，S2 仍受既有世界损坏阻断
- 严重级别：P0（阻断正常挂单，并造成误导性失败反馈）
- 影响范围：标准商品市场限价撮合、银行冻结结算、终端动作反馈
- 不影响：定制市场挂牌、汇率兑换、已经完成的历史成交与托管领取

## 结论

标准市场不能让同一账户的买单和卖单互相成交。撮合选择对手单时，必须自动跳过订单所有者与当前主动单所有者相同的委托，并继续按价格优先、时间优先查找下一笔可成交的外部委托。

修复前的实现没有在进入结算前排除自成交。银行层随后正确拒绝同一账户之间的冻结资金结算，但这一拒绝发生得太晚，导致玩家看到“同步失败”，也使原本合法的卖单无法继续与其他玩家的买单撮合或进入订单簿。

## 用户可见现象

2026-08-17 实机批量测试中，玩家先以 `80 GT` 提交铁锭买单。该买单成交 `995` 个后仍有 `2,130` 个未成交数量挂在买盘第一档。

随后同一玩家尝试提交可与该买盘交叉的铁锭卖单时：

- 终端显示“操作未完成 / 服务端暂时无法完成此操作，请稍后刷新重试”。
- 详情页账户状态显示“同步失败”。
- 卖单没有成功挂入订单簿。
- 现有买单、冻结资金与已完成成交没有被客户端自行改写。

这不是网络同步故障，而是撮合尝试拿同一玩家的买单作为卖单对手方，直到银行结算阶段才被拒绝。


调用路径为：

```text
StandardizedSpotMarketService.matchSellOrder / executeMatching
  -> MarketSettlementFacade.settleFromFrozenFunds
  -> BankingApplicationService.settleFrozenTransfer
```

银行层的同账户转账保护行为正确；缺陷位于市场撮合候选选择阶段。

## 根因判断

修复前的撮合按商品、价格和时间选取最优对手单，但没有把 `对手单所有者 != 主动单所有者` 纳入候选约束。

因此，当订单簿最优价恰好属于当前玩家时，撮合服务会：

1. 选中玩家自己的对手单。
2. 尝试从买方冻结资金向卖方账户结算。
3. 银行层发现付款账户与收款账户相同并抛出异常。
4. 当前下单事务回滚，终端只得到经过泛化处理的“同步失败”提示。

依赖银行异常来阻止自成交不符合撮合职责边界。银行保护只能作为最后一道安全防线，不能代替市场层的自成交过滤。

## 正确行为

### 撮合规则

- 买单撮合卖盘时，自动跳过属于同一账户的卖单。
- 卖单撮合买盘时，自动跳过属于同一账户的买单。
- 跳过自己的订单后，继续按价格优先、时间优先选择下一笔符合价格条件的外部订单。
- 被跳过的自有订单保持原状态、数量、版本与资金或资产托管，不得取消、改价或移动优先级。
- 如果可交叉价位内只有自己的对手单，当前新订单不得自成交；限价单应按正常规则保留未成交数量并进入订单簿。
- 不得为了绕过自成交而越过当前订单的限价。

### 反馈规则

- 自动绕过属于正常撮合行为，不应显示错误 Toast。
- 若下单因其他业务约束失败，终端必须显示真实、可理解的业务原因，不得再把撮合或银行异常统称为“同步失败”。
- 客户端刷新只能读取服务端最终结果，不能自行推断或补写资产状态。

## 安全与一致性要求

- 自成交判断必须使用服务端认证玩家映射出的真实账户身份，不能相信客户端提交的账户所有者。
- 买卖双方账户相同时，市场结算、税费、托管转移和成交记录均不得执行。
- 银行层 `fromAccountId != toAccountId` 校验必须保留，作为撮合层漏检时的最终安全防线。
- 跳过自有订单的扫描必须保证游标前进，不能反复选中同一订单形成死循环。
- 并发情况下仍需在锁定或版本校验后再次确认双方订单所有者、状态与剩余量。

## 修复验收用例

1. 买盘最优价属于自己、次优价属于其他玩家：卖单跳过自己的买单，并在限价允许时成交次优外部买单。
2. 卖盘最优价属于自己、次优价属于其他玩家：买单跳过自己的卖单，并在限价允许时成交次优外部卖单。
3. 可交叉范围内只有自己的对手单：不生成成交、不收税、不移动托管；新限价单以剩余量正常挂单。
4. 自有订单前后夹有多笔外部订单：保持外部订单原有价格优先、时间优先顺序。
5. 部分成交后遇到自有对手单：跳过自有单，并继续撮合后续合格外部单；剩余量计算正确。
6. 并发撤单或成交改变候选状态：重读状态和版本后继续扫描，不重复结算。
7. 银行账本、市场成交、税费、托管与恢复日志中不存在同一账户作为同一笔成交买卖双方的记录。
8. 终端不再把该场景显示为“同步失败”，订单簿与账户摘要刷新后与服务端结果一致。
