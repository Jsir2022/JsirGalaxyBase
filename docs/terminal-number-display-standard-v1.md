# 终端数字显示规范 v1

日期：2026-08-18

## 目标

终端不能用一种格式处理所有数字。数字格式由业务语义决定：紧凑区域帮助玩家快速扫视，涉及资产、价格与操作结果的区域必须保留精确值。缩写只改变显示，不改变服务端合同、订单参数或账本数据。

## 三类格式

### 1. 紧凑数量

适用于空间受限且只读的盘口、行情图坐标、最新成交列表和商品概览成交量。

- 绝对值小于 `1,000` 时显示完整整数。
- 从 `1,000` 起使用十进制 SI 后缀：`K -> M -> G -> T -> P -> E`。
- 最多保留三位有效数字，不强制补零：`1K`、`2.03K`、`12.3K`、`123K`、`1.23M`。
- 对市场深度向零截断，不四舍五入，从而不夸大可成交数量。例如 `12,399` 显示 `12.3K`，`999,999` 显示 `999K`。
- 紧凑值只用于阅读；点击盘口、悬停明细或进入订单页时必须回到原始精确值。

### 2. 精确分组值

适用于银行可用余额、冻结资金、资产总量、价格、手续费、成交金额及账户摘要。

- 使用千分位提高数量级辨识度，例如 `1,840,230 GT`。
- 价格不使用 `K/M/G/T` 缩写，避免把交易价格和数量级近似混在一起。
- 币种原有小数位合同保持不变；本规范不擅自改变资产精度。

### 3. 精确操作值

适用于下单输入、撤单确认、成交确认、订单与资产中心、Toast 定位详情、错误与恢复记录。

- 必须显示完整精确值，可使用千分位。
- 不允许把缩写后的字符串反解析为请求参数。
- 盘口紧凑行使用无空格的 `价格x数量`，避免通用标签在价格与数量之间换行。
- 盘口点击必须使用服务端快照携带的原始价格和剩余数量；`80x2.03K` 打开订单时仍应填入价格 `80`、数量 `2030`。

## 页面映射

| 页面位置 | 价格 | 数量 | 金额/余额 |
| --- | --- | --- | --- |
| 标准市场盘口 | 精确 | 紧凑 | 不适用 |
| 最新成交窄列表 | 精确 | 紧凑 | 不适用 |
| 行情图坐标 | 精确价格 | 紧凑成交量 | 紧凑统计值 |
| 行情图悬停 | 精确 | 精确 | 精确 |
| 商品 Hover | 精确 | 精确 | 精确 |
| 银行和账户摘要 | 不适用 | 精确 | 精确千分位 |
| 下单/撤单/成交确认 | 精确 | 精确 | 精确千分位 |
| 订单与资产中心 | 精确 | 精确 | 精确千分位 |
| Vault 格位缩略图 | 不适用 | 紧凑 | 不适用 |
| Vault 已选数量 | 不适用 | 精确 | 不适用 |

Vault 格位中的紧凑数量必须在格位右下角缩放并右对齐，不能覆盖相邻格位；已选数量在弹窗底部恢复完整千分位。

## 安全与验收

- 格式化只发生在客户端显示层，服务端仍传输并校验原始整数。
- 紧凑值不得进入订单、撤单、结算、恢复或审计请求。
- 覆盖 `999 / 1,000 / 2,030 / 12,399 / 123,999 / 999,999 / 1,000,000` 及负值、`Long.MIN_VALUE` 边界。
- 紧凑行在支持的终端最小宽度下必须保持单行；无法容纳时优先减少视觉小数位，不隐藏整个数量。
- 银行、确认框、订单中心与日志回归检查必须继续看到精确千分位数字。
- 成交比例计算不得先执行可能溢出的 `数量 * 100`；长整型边界仍需得到正确百分比。
