## 2. 两个项目解决的不是同一层问题

### 2.1 ASE：以真实储备平滑商品市场

ASE 的核心不是股票交易，而是给市场增加一个受控库存缓冲器：

1. 为每种商品设置 Saving（低价吸储）和 Spending（高价投放）目标。
2. 市价进入目标区间时，从市场买入库存或把库存卖回市场。
3. 储备按地区保存，再汇总到国家与市场层；国家可以指定允许商品和优先地区。
4. 买入消耗财政，卖出返还财政；库存不是凭空生成的统计数字。
5. AI 与玩家使用相同机制，但 AI 有商品优先级和市场所有者目标约束。

第一轮源码中可见的稳定性设计：

- 默认储备尺度为 52 周，硬上限 104 周，并允许通过规则在 0.25 到 2.0 倍间调整。
- 买卖目标使用不同储备系数（源码常量为 0.75 与 0.25）并带 5% 价格目标余量，避免在单一阈值附近频繁反向操作。
- 先采集市场原始订单，再扣除储备系统自己造成的订单，避免控制器把自己的影响误判成外部需求。
- 算法明确分成初始化、旧转移清理、市场数据采集、国家/地区数据采集、执行、储备重算和限幅。
- 对整数范围、定点小数、变量上限和极端 GDP 做显式保护；性能敏感公式甚至使用预计算常量。
- 市场合并、国家释放、革命、战争结束和等级变化都有修复/重算入口，说明作者把生命周期一致性视为核心问题。

主要源码入口：

- `src/common/script_values/ase_stockpiling_values.txt`：容量、目标、限幅与价格条件。
- `src/common/scripted_triggers/ase_stockpiling_triggers.txt`：何时允许吸储/投放以及 AI 决策。
- `src/common/scripted_effects/ase_stockpiling_effects.txt`：完整批处理流水线。
- `src/common/on_actions/ase_on_actions.txt`：周期与世界状态变化后的重算。
- `src/gui/000_ase_stockpile_panel.gui`：玩家看到的控制面。

### 2.2 E&F：把商品经济向货币和金融体系延伸

E&F 的目标更宏观。当前源码包含：

- 金银需求、金本位/银本位/复本位等货币制度；
- 每国货币、货币供应量、国内外持币、黄金计价与汇率；
- 中央银行、私人银行、利率、贷款和外汇控制；
- 国债及 5 年/10 年利息，债券供需和价格；
- 制造业、农业、铁路、采矿等股票或金融产品及市场指数；
- 市场流动性、通胀、货币升贬值预测；
- 结合债务/GDP、人均 GDP、增长、币值、通胀、生活水平、识字率、恶名、合法性、军力、工资和税率的综合信用评级；
- 金融危机、经济危机、货币危机与破产事件。

其主循环以月度脉冲为核心，按国家当前制度和设施更新中央银行、货币、库存、战争/革命状态及金融变量。它把债券和股票
也做成市场商品，让供需进入价格，再由价格和宏观变量反过来影响融资与信用。这种“实体商品—货币—银行—证券—危机”
的闭环正是它与 Galaxy Base 长期制度方向相似的地方。

主要源码入口：

- `common/scripted_effects/00_on_action_main.txt`：月度总调度。
- `common/script_values/00_economic_scripted_value.txt`：金银、危机、库存和国家经济指标。
- `common/script_values/01_economic_currency_scripted_value.txt`：货币估值、供应、境外持币和汇率；单文件约 11 MB，含大量按币种展开的生成逻辑。
- `common/script_values/00_financial_scripted_value.txt`：信用评分、债券、股票、利率和金融指数。
- `common/scripted_effects/01_economic_scripted_effects.txt` 与 `01_financial_scripted_effects.txt`：状态推进。
- `common/buildings/ef_15_bank.txt`、`ef_16_financial_centre.txt`：银行和金融中心作为经济主体。
- `common/laws/01_ef_monetary_system.txt`、`01_ef_monetary_policy.txt`、`01_ef_currency_type.txt`：制度与政策。

## 3. 对 GTNH 商品经济真正有价值的思想

### 3.1 第一优先：库存覆盖率，而不是凭空调价

GTNH 物品有真实生产成本和真实库存，因此价格信号应建立在可验证事实之上：市场可卖库存、近期成交消耗速度、
`库存覆盖时间 = 可用库存 / 平滑后的单位时间成交量`、挂单深度与买卖价差，以及公共任务产生的净流入流出。
ASE 的“按若干周需求定义储备目标”可改写为适合服务器节奏的“小时/天覆盖率”。

### 3.2 第二优先：公共储备作为有限市场参与者

后续可设计一个 PostgreSQL 真源的银河储备库：

- 只对正式目录中少量基础商品启用，并配置目标覆盖率、最大库存、单周期交易量和预算。
- 库存低且价格异常高时有限投放；库存高且价格异常低时有限吸储。
- 必须实际存取物品和公共账户资金；储备订单与玩家订单一样进入撮合、费用、审计和恢复链。
- 控制器计算需求时扣除自己的挂单和成交，防止自激振荡。

它只能提供有限流动性和灾后恢复能力，不能承诺固定价格，也不能无限印钱或生成物品。

### 3.3 第三优先：把状态解释给玩家

市场应回答商品为什么涨跌、当前是缺货还是成交稀疏、库存还能覆盖多久、变化来自真实成交还是公共储备，以及资金为何锁定、
物品在哪里、失败后如何恢复。标准市场详情可逐步增加“供需压力、覆盖率、价差、活跃度、价格驱动”五项解释指标；所有
指标从现有订单、成交、Vault 和交付真源派生，不建第二套流水。

### 3.4 后置：信用与货币

E&F 的信用、债券和货币系统很有启发，但不应立即复制。信用必须对应借贷额度、抵押、违约和清算；多币种只有在跨群组服
经济主体和真实兑换需求出现后才成立；债券必须有发行人、用途、期限、利息来源和违约规则。

## 4. 不可直接照搬的部分

- Victoria 3 使用聚合订单、脚本变量和隐藏建筑模拟库存；Base 必须坚持真实 `ItemStack`、Vault/Cell、银行账本与 PostgreSQL 事务守恒。
- E&F 当前工作树约 1.7 GB、1294 个文件，并有大量按国家/币种/商品展开的生成逻辑；Java 实现应采用表驱动规则和版本化配置。
- 月度脉冲不适合服务器每 Tick 全量扫描；Base 应使用成交事件驱动、增量聚合和低频有界调度。
- 不引入无法解释或无法审计的模拟供需；任何影响资产的动作必须有业务键、幂等、版本、审计和恢复路径。
- E&F 无明确许可证，禁止复制其代码、数据、GUI 或美术资源。

## 5. 建议阶段

1. **R1 经济事实盘点**：只读检查现有订单、成交、银行、Vault、交付和恢复事实；离线计算成交速度、覆盖率、价差与波动。
2. **R2 经济观测页**：只增加指标和原因解释，不调价、不替玩家交易；定义时间窗、稀疏数据降级和异常值限幅。
3. **R3 公共储备离线回放**：以历史数据比较双阈值、目标覆盖率、预算和单周期限额，观察自激、库存耗尽和资金占用。
4. **R4 SHADOW/ENFORCE**：SHADOW 只记录本应产生的订单；稳定后才对白名单基础商品启用真实撮合。
5. **R5 金融扩展单独立项**：按真实需求分别评估借贷/信用、公共工程债券、企业权益和跨服货币。

## 6. 当前结论

短期最值得采用的是 ASE 的“真实库存 + 目标覆盖率 + 双阈值滞回 + 有界操作 + 扣除自身影响”；E&F 最有价值的是长期
制度地图和指标关联，而不是其具体脚本实现。下一步应先完成 R1 数据事实盘点和离线指标计算，再决定是否需要公共储备；
当前不修改撮合、银行、Vault、数据库或生产服务器。
